## 7.3 简历项目打磨模板与高频面试追问指南

### 一、标准简历项目经历示例（请将 `XX` 替换为你第 5、6 章跑出的真实数字！）

> **项目名称**：基于 AMD ROCm 平台的本地个人知识助手构建与轻量微调加速  
> **一句话总括（适合简历摘要栏）**：*基于 AMD 平台完成小模型微调并构建本地学习助手，负责数据整理、模型服务与知识检索集成，通过自建测试集评估微调前后及应用效果。*  
> **STAR 法则量化要点拆解**：  
> - **本地服务部署与多端集成**：基于 `vLLM` / `llama-server` 在 AMD GPU 上部署 OpenAI 兼容推理服务，打通 WorkBuddy 与 `Qoder` 工作流；基于 `FastMCP` 将本地 Obsidian 双链笔记库封装为可复用的**知识管理 MCP 服务**，结合渐进式 `SKILL.md` 降低系统提示词显存开销；  
> - **中文数据清洗与 LoRA 微调**：针对 4B 参数小模型在中文口语通知结构化抽取（或特定风格生成）上的格式失稳问题，清洗脱敏构建 **XXX 条** 中文指令样本完成单卡 LoRA 微调，在独立构建的 **50 题** 黄金测试集上，JSON 合法率由 **XX%** 提升至 **XX%**，字段精确匹配率提升 **XX 个百分点**；  
> - **量化压缩与推理加速**：采用 `AMD Quark` 对模型执行 INT4 分组量化并对比前后性能，权重体积缩减 **XX%**、峰值显存下降 **XX%**；结合 Prefix Caching 前缀缓存与 `AITER` / `hipBLASLt` 融合算子，多轮 Agent 调用首字延迟（TTFT）降低 **XX%**，生成速度达 **XX tok/s**。

### 二、面试官最爱追问的 3 道真题与满分答法思路

1. **问：“既然有现成的云端大模型 API，你为什么要在本地部署并微调 4B/8B 小模型？”**
   - *答法要点*：从 **数据隐私边界**（个人笔记、内部财务/单据不可出内网）、**高频定时与批量处理的零边际成本**（每日定时跑表、精翻整本 PDF）以及 **垂直结构化任务小模型微调后的高性价比**（微调后 4B 模型在特定 JSON 提取准确率上逼近大模型，但延迟与显存成本仅十分之一）三层作答。
2. **问：“你的知识库问答怎么防止小模型胡编乱造（幻觉）？”**
   - *答法要点*：① 文档预处理按 Markdown 标题语义结构切分避免跨段落串台；② MCP 检索返回精确文件名与片段；③ 提示词/Skill 强制要求标注 `[[出处角标]]` 并设置“未提及则明确拒答”锁，且通过包含超纲陷阱题的自建测试集验证。
3. **问：“连接桌面 Agent 后首字响应很慢，你是怎么定位和解决的？”**
   - *答法要点*：区分 Prefill（TTFT 算力密集）与 Decode（TPS 带宽密集）；定位到客户端每轮重复携带上万字工具定义导致重复 Prefill，通过开启 **Prefix Caching** 复用 KV Cache 化解首字等待，再通过 `AMD Quark` 量化减少权重搬运带宽实现 TPS 翻倍。
