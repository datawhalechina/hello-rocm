## 一、现有项目上下文分析与痛点诊断

### 1.1 现有项目结构与资产盘点

当前 `hello-rocm` 基于 **VitePress** 构建中英文双语文档站（`docs/zh/`、`docs/en/`）并配套源码目录（`src/`），现有结构分为 6 个模块：

- `00-environment/`：ROCm 10.0.0（TheRock + ROCm.AI）、Windows/Ubuntu 环境安装、`gfx` 架构表、Ryzen AI XDNA2 NPU（FastFlowLM / Lemonade）。
- `01-deploy/`：按模型（Qwen3 / Qwen3.5 / Qwen3.6 / Gemma4 / MiniCPM / MiniCPM-V / MiniCPM-o）平铺 LM Studio、vLLM、Ollama、llama.cpp、FastFlowLM、Lemonade 部署文档。
- `02-fine-tune/`：SFT 原理、`transformers + peft` LoRA 微调（Qwen3-0.6B、Qwen3.5-4B、Gemma4-E4B）及 SwanLab 记录。
- `03-infra/`：AMD 硬件全景、`ldd` 软件栈追踪、SIMT 架构、C++ 手写 HIP Kernel、PyTorch 自定义算子与 Autograd 集成。
- `04-references/`：ROCm 官方文档、架构白皮书、`hello-rocm-skill` 索引。
- `05-amd-yes/`：大杂烩式案例集（`toy-cli`、`minesweeper-agent`、YOLOv10 微信跳一跳、Chat-甄嬛、智能旅行规划、OpenClaw、Torch-RecHub 推荐系统、Every Embodied 具身智能、100GB+ Strix Halo 原生 HIP 部署、`happy-llm` 分布式预训练）。
- `learning/20-day-learning-plan.md`：纯云端无 GUI 的 20 天打卡计划（含 5 天手写 HIP 算子）。

### 1.2 为什么现有课程「太技术、不好学习」？（核心痛点诊断）

| 维度 | 现有课程痛点 | 重构方向（小白友好 & 获得感优先） |
|:---|:---|:---|

## 二、原始需求与项目特性规范

### 2.1 品牌与核心定位

- **项目名称**：`hello-rocm`
- **核心标语（Slogan）**：每个 AI 小白，从零开始，动手实践的第一站。
- **副标题（定位）**：基于 AMD 平台的 AI 与 Agentic AI 入门实践手册。
- **成功故事主线**：「我把自己的 AMD 电脑，变成了学习和工作的 AI 助手。」

### 2.2 核心教学链路要求

1. **最低成本本地模型部署**：面向有 AMD 显卡的学习者，采用 `llama.cpp`、`vLLM` 等工具低成本跑起本地模型。
2. **直观认识数据类型与硬件资源**：不堆砌底层数学公式，直观讲清「参数量 vs 权重文件大小 vs 运行内存/显存」的区别，以及同一个模型为什么有不同精度版本（BF16/FP16/FP8/Q8/Q4 等）、该如何根据自己的硬件选择。
3. **接入日常效率工具**：接入 **WorkBuddy**、**Codex**、**VS Code 相关助手**等现有成熟工具，**发布经过验证的版本号与配置文件**。
4. **Agentic AI 核心课程**：覆盖 **提示词（Prompt）课程**、**个人知识库（RAG）**、**Agent 相关工具（Tool Calling / MCP / Skills）**。
5. **痛点驱动的模型进阶**：
   - 发现模型能力不够（不懂专有知识/格式不稳/风格不符） → **模型微调（Fine-tuning）** + 自建测试集前后对比评测。
   - 发现模型速度不够（首字慢/吞吐低/长上下文爆显存） → **模型推理优化（Inference Optimization）**。
6. **12—15 个趣味案例**：覆盖 **编程助手、个人知识库、论文阅读、文件整理、报告生成、语音交互、游戏互动、任务规划** 八大方向。
7. **统一案例标准与试学机制**：
   - 每个案例必须包含：**代码、演示、支持配置、验证方法、扩展任务**。
   - 建立**新手试学机制**，邀请新手实操试学，持续迭代完善常见问题（FAQ）。
8. **作品与简历成果**：
   - 沉淀：**应用代码、演示、训练或微调记录、效果评估（自建测试集）和个人贡献说明**。
   - 能力证明：**模型部署、数据处理、应用集成与评测能力**。
   - 配套简历示例与撰写指南。

## 三、需求理解与智能决策预案（V1 初稿构想）

基于对现有仓库资产与 AI 教学最佳实践的分析，初步将重构后的课程设计为 **「6 阶渐进式主线 + 1 个趣味案例库 + 1 套成长与简历闭环」**：

- **Stage 0｜认识你的 AMD AI 装备与模型直觉（零门槛热身）**：显卡/APU/云算力快速自检；直观搞懂参数量（B）、权重体积（GB）、运行显存（含上下文 KV Cache）与量化精度（FP16/Q8/Q4）的「买菜算账法则」；按显存对号入座选模型。
- **Stage 1｜第一站：最低成本跑起你的第一个本地模型**：`llama.cpp`（单人轻量极速启动）与 `vLLM`（高性能标准 API 服务）双主线实操，统一暴露本地 OpenAI 兼容接口。
- **Stage 2｜接入日常工具：把本地模型变成全天候助手**：手把手接入 **WorkBuddy**（AI 办公工作台）、**Codex**（终端编程 Agent）、**VS Code AI 助手**（Cline / Continue 等），提供经过实测验证的软件版本、模型档位与一键配置模板。
- **Stage 3｜玩转 Agentic AI：提示词、知识库与工具调用**：提示词工程实战（让本地小模型听懂复杂指令） → 本地个人知识库（RAG 检索增强） → Agent 工具链（Function Calling、MCP 协议与 Skills 接入）。
- **Stage 4｜能力不够怎么办？动手做第一次模型微调**：问题诊断（什么时候该用 Prompt/RAG，什么时候必须微调） → 数据清洗与构造 → LoRA 轻量微调实战 + SwanLab 记录 → **自建测试集评估微调前后效果**并重新部署上线。
- **Stage 5｜速度不够怎么办？动手做模型推理优化**：问题诊断（首字延迟 TTFT vs 生成速度 TPS vs 显存瓶颈） → 精度与量化损耗平衡 → Prefix Caching（解决 Agent/WorkBuddy 超长系统提示词延迟）与 KV Cache 优化 → `vLLM` / `llama.cpp` 并发与引擎参数调优。
- **Stage 6｜12—15 个趣味案例实战营 + 作品集与简历锻造**：覆盖 8 大场景的分级趣味案例（复用升级仓库已有的 `toy-cli`、`minesweeper-agent`、`smart-travel-planner`、`MiniCPM-o` 语音、`openclaw` 等优质素材，并补齐 WorkBuddy/VS Code 论文阅读、文件整理、报告生成、个人知识库等全新高实用案例），配套统一五要素规范、新手试学清单与简历成果产出模板。
